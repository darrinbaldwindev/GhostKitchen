# CHATGPT Overseer Handoff

## Operating chain
CHATGPT Head Overseer → GhostKitchen Project Overseer → authorised worker(s) → verification → project log → CHATGPT Head Overseer.

## Rules
- Fresh repository state before substantive work.
- Explicit task identity, scope, authority and acceptance criteria.
- Repository/test evidence determines completion.
- Gemini/Manus intelligence is input only unless correlated execution evidence exists.
- Fail closed on missing authority, credentials, capability or production gates.
- No production/destructive changes without existing project gates.

## Current P0 focus
Prioritise evidence-backed Model B unit economics, pilot concept evaluation, and the order-to-delivery operating model in dependency order. Do not treat candidate concepts or financial assumptions as final commercial decisions until evidence gates are passed.

## Reporting contract
Every handoff should report STATUS, task/mission ID, decision-maker, executor, verifier, evidence, tests, changes, blocker and next authorised action.
